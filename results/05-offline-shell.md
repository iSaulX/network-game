## Implementation notes

### Why the hand-written worker instead of Serwist

`@serwist/turbopack` 9.5.13 is the current stable Turbopack integration. Its route-handler implementation is explicitly labelled “for when NOT using `cacheComponents`”, and this app enables `cacheComponents: true` plus `partialPrefetching: true`. The 10.x line is still a preview. `@serwist/next` is the webpack plugin and cannot run in the Turbopack production build. The brief allows a hand-written worker plus a generated precache manifest when Serwist cannot build with this Next/Turbopack setup; that fallback was chosen rather than adding a preview/incompatible dependency. No Serwist packages were installed.

### Precache

The current production build generates **95 entries / 54.9 MiB**:

- routes `/`, `/alone`, `/play`, `/offline`;
- `/manifest.webmanifest` and `/favicon.ico`;
- every file under `/_next/static/**` (JS chunks, CSS, hashed `next/font` media, build manifests);
- every file under `public/` (PWA icons, all avatar PFPs, chip/token art, die faces/source art, mode art, both supplied MP3s, font originals and unused starter SVGs), excluding the generated `public/sw.js`/`swe-worker*`.

The build ID from `.next/BUILD_ID` is the cache revision (`parchis-stars-<buildId>`). Installation fetches the list with `cache: "reload"` at concurrency 6, retries failed entries once, and logs any persistent failures without preventing the worker from installing.

### Runtime policies

- **Documents:** network-first with a 3 s timeout and navigation preload. A network 5xx, timeout or failure returns the matching cached route (`/`, `/alone`, `/play`, `/offline`; query strings ignored); other paths return the cached `/offline`. A network 4xx is a legitimate response and is returned.
- **Static assets:** cache-first from the precache, with a runtime cache for uncached same-origin static files. Audio Range requests are answered with a `206 Partial Content` slice, including suffix ranges.
- **`next/image`:** the optimized response is cached after first use. Offline, or when the optimizer fails, the worker extracts the `url` query parameter and returns the original precached public image. This is what makes avatar changes, mode art and die faces work on a cold offline load without precaching every width.
- **API/WebSocket boundary:** `/api/*` is returned to the browser untouched; WebSocket traffic is not intercepted. No background sync, offline mutation queue, push or party data caching.
- **Client-router payloads:** requests carrying `RSC` or `Next-Router-Prefetch` headers are network-only. Offline, Next.js falls back to a normal document navigation, which the worker serves; the `/play` → **Volver al inicio** path was verified to land on `/` offline this way.
- **Caches:** activation deletes every `parchis-stars-*` cache with a different build ID, enables navigation preload, and claims clients. `skipWaiting: true`; no automatic page reload and no update-prompt UI.

### Registration, indicator and headers

- Registration is skipped entirely in development; leftover workers from an earlier production run on the same origin are unregistered there so HMR is never controlled by a stale cache. It is also skipped outside a secure context or when `serviceWorker` is unavailable.
- The offline indicator reads `navigator.onLine` only as a hint and never disables online actions.
- `/sw.js` and `/manifest.webmanifest` headers were verified with `curl` on the production server.

## Deviations, caveats and follow-ups

- **Serwist fallback documented above.** The worker is hand-written; no Serwist package or `serwist.config.js` was added.
- **Task 04 custom server absent.** The repository has no `server.ts`, so production verification used `next build && next start` on port 3100. `start` remains `next start`; when Task 04 lands, the service worker must still be served by that server with the configured headers and must not intercept `/api/ws`.
- **Offline gameplay is intentionally beyond the Task 05 shell scope** because of the direct user request. `/alone` and `/play` are fully precached; online party APIs remain connectivity-only. The Task 06 `/bots` route, `GameStage` abstraction, homepage entry and versioned `localStorage` resume remain pending.
- **Precache size is ~55 MiB** because every public file (including unused source art and duplicate font originals) is cached, per “cache it everything”. This guarantees no missing game asset but makes the first install download large. A future optimization could precache only runtime assets or generate optimized image variants.
- **`next/image` offline fallback returns the original public image**, not the resized optimizer output, for sizes that were never fetched online. It renders correctly but is larger; optimized responses are cached after their first online use.
- **RSC payloads are not precached.** Next.js falls back to document navigation when a client-router fetch fails offline; verified. If a future route relies on client-side navigation without a network, precache its RSC payloads or add a deliberate offline handler.
- **Installed-PWA launch was simulated** by opening a brand-new offline Chrome target at the manifest `start_url` `/alone`; the browser was not manually installed from the UI. `Page.getInstallabilityErrors()` was empty, and the manifest/start URL/icons are correct.
- **iOS was not tested** (no device available). iOS does not support `display: fullscreen`; it launches the installed web app in WebKit's standalone-style view regardless of the manifest, and uses `apple-touch-icon`/`appleWebApp.title`.
- **`public/sw.js` is generated.** It is created by `bun run build` (or `bun run build:sw`) and ignored by git; running `next start` without that build step will not serve the latest worker.
- **No install/update prompt, background sync, push notifications or forced reloads** were added; updates activate on the next load and old caches are removed. A running game may have its old cache removed when a new build activates, as required by `skipWaiting`; no automatic page reload is performed.
- **ESLint scope change:** `.agents/**` was already failing with third-party lint errors before this task; it is now ignored alongside generated `public/sw.js` so `bun run lint` covers application code cleanly.
- **No secrets, tokens or party data** are written to Cache Storage or `localStorage` by this task. The cache report was checked for `/api/*` and found none.
